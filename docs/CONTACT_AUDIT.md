# 站立滑移诊断与网页模型修正

2026-11-07。冻结策略与关节增益不变；对原生MuJoCo 3.12执行27组设置/时长对照，再用真实浏览器WASM验证。完整数值见[诊断JSON](contact-audit.json)。

结论：原地面与脚底滑动摩擦系数已经为1.0，并非漏设摩擦。将其增大到3.0，20秒左右脚净位移反而从45.2/8.9 mm增至62.0/61.1 mm。原模型5 ms积分、默认软摩擦约束会产生可见漂移；改变接触求解精度能在同一策略下明显改善。不能把所有足部运动都称为滑移，也不能承诺完全不动。

| 无外力站立条件 | 2–60秒左/右脚原点净位移 | 承载接触切向速度P95 |
|---|---:|---:|
| 原模型：5 ms、pyramidal、NoSlip关闭、μ=1 | 44.7 / 24.7 mm | 12.86 mm/s |
| 仅改为1 ms | 46.4 / 28.6 mm | 4.28 mm/s |
| 仅开启NoSlip20 | 20.0 / 6.2 mm | 21.64 mm/s |
| 网页采用：1 ms、elliptic、impratio10、NoSlip20、μ=1 | 8.4 / 1.1 mm | 2.56 mm/s |

这说明单独提高摩擦、只减小步长或只开NoSlip都不能完整解决观察到的现象。网页采用组合设置，保持原摩擦、几何、质量、关节增益、网络、50 Hz推理及200 Hz目标滤波/观测采样不变；每个5 ms目标保持期间推进五次1 ms物理步。

5分钟持续站立对照：原设置左/右脚净位移42.5/24.8 mm，改进设置17.3/1.9 mm；接触切向速度P95为2.44→1.76 mm/s。60秒和300秒是不同统计窗口，净位移不是累计滑动距离，也不一定随时间单调增加。初始2秒落地过程均排除。

原设置60秒内，达到95%摩擦容量的承载接触约0.009%，不支持“主要是摩擦上限过低”的解释。速度通过承载接触点雅可比乘广义速度得到，并投影到接触切平面；每个接触法向载荷须大于5 N。脚原点位置还会受足部滚动、转动和平衡调整影响，不能直接等同于纯滑移。

浏览器WASM还执行60秒无外力站立回归，验收阈值为左右脚净位移<20/<15 mm；实际结果保存于`validation-{local,ci,public}.json`的`standing`字段。每组动作与弹簧组合持续22秒，覆盖两次参考循环；循环不重置根位姿、滤波、历史或启动计数。鼠标直接拖机器人只施力，拖空白只旋转视角，均有真实指针事件测试。

没有锁定脚、固定浮动基座、改写仿真位姿或增加抵消滑移的外力；相机默认固定世界坐标，不随根位置移动。脚的世界XY绝对误差不在原策略的直接观测中，剩余姿态摆动与位移仍须如实展示。上述改善属于仿真接触精度调整，不是训练质量提升，也不能当作实机摩擦标定。

原训练/部署/历史评估模型保持只读。网页模型修改项及源SHA在`ASSET_PROVENANCE.json`中明示；带hash的配置和MJCF文件名避免浏览器将新代码与旧缓存的接触模型混用。ONNX哈希仍为`726ca9fd62520498125186e19a5fbc1d9e8d6607245852ca91cb167592d6df21`。

本机复现主要对照：

```bash
bash scripts/resource.sh /home/mapinxuan/gentle-r1/deployment/.venv/bin/python \
  scripts/contact-audit.py --seconds 60 \
  --variants baseline mu3 noslip20 elliptic10-dt1000-noslip20 \

```

该脚本读取冻结原始模型，明确设置每个变体，不会把修正后的网页模型冒充原始基线。CPU8/9、内存上限、全局仿真锁由保护入口执行；不加载Isaac或NVIDIA渲染。

机制参考：[MuJoCo摩擦阻抗与NoSlip参数](https://mujoco.readthedocs.io/en/stable/XMLreference.html#option)、[接触与NoSlip求解](https://mujoco.readthedocs.io/en/stable/computation/index.html)。这些方法降低软约束滑移，不保证数学意义上的精确粘着。
