# 参考动作切换修正

2026-11-07。用户发现选择前伸/抬臂后，界面仍显示站立说明，实际机器人也不抬臂。问题已定位到动作导出与加载失败处理。

原抬臂/前伸参考的位置轨迹在循环边界连续，但速度由`np.gradient`计算，末帧使用单边差分，产生约0.011175/0.013410 rad/s的非零速度；起始速度为零。新增的严格循环检查因此拒绝加载两段动作。界面捕获异常后仍保留新选项，按运行又清除错误，使旧站立动作看起来像切换成功。

修正：

- 用平滑三次曲线的解析导数生成关节速度，保证位置/速度端点都连续。位置轨迹、冻结权重、观测契约和物理设置不变。
- 每个动作JSON采用hash文件名，新配置指向新文件，避免旧端点速度缓存。
- 加载时禁止运行/复位；失败恢复实际生效的选项与说明。运行中成功切换会自动继续。
- 捕获本次选择ID并保护请求顺序，迟到的旧下载不能覆盖较新的选择。

测试先在旧数据上复现`raise: joint_vel seam must be continuous`失败，再验证修正。旧验收仅检查仿真完成，未断言实际动作ID；旧raise/reach标签实际都运行stand，不能作为非站立验证证据。原27组站立接触对照与60秒站立数值仍有效。

新验收在每次选择后确认真实`sim.motionId`、数据名称、参考姿态和网络收到的目标一致；第5秒采样真实肩/肘关节，要求双臂相对站立显著运动，且抬臂与前伸产生不同的物理姿态。六组动作/弹簧组合各22秒，并覆盖5/15 N条件。单独页面注入下载失败及旧请求延迟，验证回滚、按钮禁用、最后一次选择生效。
