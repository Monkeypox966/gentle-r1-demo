[实际步行画面](dynamic-walk.png) · [双臂挥动画面](dynamic-wave.png) · [加载完成提示](interaction-help.png)

所有动作均为自主生成，生成器不读取训练动作。其目标是展示同一冻结策略在自然、可达且已验证的参考上的跟踪与受扰响应，而不是把合成片段当作未见动捕数据的泛化证据。没有更换策略、改写物理姿态、锁脚或放宽保护。

| 动作 | 参考设计 | 浏览器无外力物理结果，22秒 |
|---|---|---|
| 双臂挥动 | 平滑抬臂、屈肘和周期性摆腕 | 双肩实际活动范围约0.51/0.54rad |
| 转腰摆臂 | 转腰±0.30rad，配合双臂运动 | 腰部实际活动范围约0.45rad |
| 连续浅蹲 | 足端位置/方向约束逆运动学，根高度下降65mm | 实际根高度活动范围约56mm，双膝约0.56/0.57rad |
| 向前步行 | 0.18m/s、步态周期1.25秒、参考足端抬高55mm、横向重心摆动55mm | 实际前进约3.79m，双脚原点高度活动范围约77/75mm |

步行起初较慢的候选（0.10m/s、2秒步态）虽然存活，但前进不足，因此没有选入正式资源。发布轨迹使用可达足端路径，先做原生MuJoCo筛选，再测真实WASM。脚原点高度变化包括足部姿态调整，不能等同于足底净离地间隙。

四种动态参考在浏览器各运行两组22秒：无外力、运动中向躯干施加10N前向轻推。均跨越两个十秒资源周期，检查真实动作ID、实际关节运动、物理前进和无保护故障；动态关节RMSE约0.051–0.071rad，统计使用启动2秒后每0.5秒的24关节样本。行走另做真实鼠标拾取/拖动、释放及继续跟踪验收。具体数值以`validation-local.json`、`validation-ci.json`和`validation-public.json`为准。

额外原生CPU测试：四动作×5/10/15N策略条件，共12组、每组32秒；第4秒加入约0.25秒的10N横向推力。全部完成，关节RMSE约0.045–0.085rad；摘要见`dynamic-native.json`。这是特定扰动测试，不代表任意拖拽力度下均稳定。

## 循环、画面与操作

- 所有参考均为501帧、50Hz，最后一帧是循环边界。位置和速度端点连续；步行允许根位置相差一个明确的循环位移。
- 步行每个10秒周期前进1.8m。未来参考跨周期时累加该位移，参考叠影也使用累计世界位置；不向策略输入突然退回原点的目标。
- 循环不复位物理、动作滤波、观测历史或启动计数。运行时切换动作仍明确复位并自动继续，不将它描述成无缝动作过渡。
- 步行相机随物理机器人移动，地面与网格固定。阴影光源范围随机器人移动，以免走出原点附近的阴影区域；光照只影响渲染。
- 直接拖机器人施力、空白拖动旋转、滚轮缩放；松开撤力。关闭加载提示不会自动启动仿真。

## 复现

网页构建无需Python。仅在本机重新生成资源/原生筛选时，复用训练项目已有的部署uv环境，不安装新的全局工具：

```bash
bash scripts/resource.sh /home/mapinxuan/gentle-r1/deployment/.venv/bin/python scripts/export-assets.py
bash scripts/resource.sh /home/mapinxuan/gentle-r1/deployment/.venv/bin/python scripts/motion-audit.py --forces 5 10 15 --push --seconds 32 --output test-results/dynamic-native.json
bash scripts/resource.sh npm test
bash scripts/resource.sh npm run build
# 另开本地preview后：
bash scripts/resource.sh npm run test:browser
```

重新导出默认保留既有独立ONNX数值对照，仅显式`--update-oracles`才更新它。原训练代码、配置、权重和部署/评估模型保持冻结；新增资源仅在网页项目内。
